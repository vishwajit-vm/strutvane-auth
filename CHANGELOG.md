# @strutvane/auth

## 0.2.0-next.1

### Minor Changes

- **The app owns its `users` table; auth ships ordinary migrations and never creates or alters a table at runtime (decision #2).** Breaking, pre-1.0 (a minor bump).
  
  - New: `migrations/2026_11_18_000001_add_auth_columns_to_users_table.ts` (adds `two_factor_secret`, `two_factor_confirmed_at`, `two_factor_last_step`, `current_team_id` to the skeleton's `users`) and `migrations/2026_11_18_000002_create_auth_tables.ts` (auth's own tables, all `internal`). Both are Schema-builder migrations, so they run on MySQL, MariaDB, PostgreSQL and SQLite and roll back cleanly.
  - `node strut auth:migration` now copies these files into `database/migrations` (never overwriting a file the app already has) instead of writing SQL; it no longer needs a database. New exports `copyAuthMigrations`, `AUTH_MIGRATIONS`, `authMigrationsDirectory`.
  - The SQLite and PostgreSQL stores no longer run DDL: `sqliteAuthStore` / `sqliteCounterStore` stop creating tables, and `SQLITE_SCHEMA`, `POSTGRES_AUTH_STATEMENTS` and `ensurePostgresAuthSchema` are removed, as are the v1 SQL files in `migrations/{postgres,sqlite}/`.
  - The stores read and write the skeleton's columns: user ids are the table's integer key (decimal strings such as `'42'`), and `email_verified_at`, `two_factor_confirmed_at`, `created_at` and `updated_at` are timestamps written like the ORM writes them. A malformed user id is "not found" before it reaches SQL. Email-verification links and system operations accept integer user ids.
  - The sessions table is now `auth_sessions` (the framework reserves `sessions`). Passkey uniqueness moves to `credential_key` (the credential id's SHA-256), so a 1024-character WebAuthn credential id fits every engine's index limit.
  - Boot checks the auth columns of `users` too, and `config/database.ts` may use the skeleton's flat shape (`pgsql`, `database` as the SQLite file; the default SQLite file is now `database/database.sqlite`).
- **`createFirstAdmin()`: the app's first administrator from a seeder, on every engine (decision #13).**
  
  `createFirstAdmin(db, { email, name?, password?, role? })` (from `@strutvane/auth`) runs on the seeder's framework connection (`SeedContext.db`), so it works on MySQL, MariaDB, PostgreSQL and SQLite without a running app. It creates the account once (email verified, scrypt hash, role `admin` by default) in one locked transaction. Without `password` it returns a generated 24-character `oneTimePassword` to show once; the password is never logged. It refuses, changing nothing, with `FirstAdminError` and a stable code: `first_admin_exists` (re-seeding is safe), `email_taken` (an existing account is never promoted), `validation_failed`, `auth_tables_missing`.
- 2d3a47a: **Joins the 0.2 core train on `@strutvane/framework` 0.2 (CONSISTENCY #123, #69, #128).** Breaking, pre-1.0 (a minor bump).
  
  - The framework peer is now `^0.2.0-next.0` (was `^0.1.0-next.1 || ^0.2.0-next.0`), and `strutvane.compat` matches it.
  - Every code is lowercase `snake_case`, like the framework's. Problems from the provider and middleware are `forbidden`, `not_found`, `validation_failed`, `tenant_required`, `malformed_request`, `unsupported_media_type` and `payload_too_large`. `InvalidFilterError` is `invalid_filter`. `AUTH_ERRORS` registers `invalid_filter`, `invalid_credentials`, `email_unavailable`, `invalid_token`, `two_factor_required`, `email_not_verified`, `tenant_required`, `malformed_request` and `unsupported_media_type`, so every problem auth returns renders with a proper title (`two_factor_required`, `email_not_verified` and `malformed_request` used to fall back to a humanized code).
  - Finding codes are lowercase too: `tenancyAudit` (`rls_disabled`, `rls_not_forced`, `no_restrictive_policy`, `runtime_role_bypasses_rls`, `runtime_role_owns_table`, `definer_view`, `security_definer_function`, `tenant_setting_default`), `findSessionSet` (`session_set`, `session_set_config`, `set_local`, `persistent_set`, `session_reset`) and `relationKeyAudit` (`relation_table_missing`, `relation_key_not_unique`). Update CI scripts that compare the old names.
  - Field issues keep `{ path, field, code, message }`, and are now checked against the framework's `ValidationIssue` type.
  - A new source-scan test fails on any uppercase code in `src`.

## 0.2.0-next.0

### Minor Changes

- 11fa5e0: Harden tenant resolution for anonymous requests, rate limiting and policy evaluation defaults.
  
  - Anonymous requests are no longer scoped to a tenant unless `tenancy.allowAnonymousTenant` allows it; the app provider honours `X-Tenant-Id` only for tenant-less service actors. `requireAuth` is now checked before tenant resolution.
  - Identity engines count requests without a peer address against a shared fallback bucket (new `allowMissingPeer` and `logger` options); IPv6 clients are limited per `/64`; the memory store evicts expired and per-IP keys before per-account keys. The app provider reads the `clientAddress` of the `http.onRequest` payload and accepts `auth.trustedProxies`.
  - The app provider binds the seed admin role to the seeded account and fails boot if it cannot be created; its `POST` endpoints require `application/json`, refuse cross-site requests (new `auth.trustedOrigins`) and stream-limit bodies to 16 KiB.
  - Policies: mistyped record values make checks throw; `role: []` is a definition error; null actor values never widen allow rules under negation; new rule/field option `scope` (`'any' | 'global' | 'tenant'`); combined rule limits are checked at definition time; new `filterableFields()` and `restrictedFields`; `maskRecord` keeps only readable schema fields and `unwritableFields` reports non-schema keys.
  - `validateFilter` accepts `allowedFields`; error reasons are escaped and truncated and no longer name tables; new `safeLabel`.
  - `diffChanges` / `recordAudit` accept `maskFor` to redact fields with read rules.
  - SQL: text comparisons use `COLLATE "C"` by default (`textCollation: 'database'` to opt out).
  - Postgres: `tenancyAudit` follows role membership, requires tenant policies to apply to every role and read the tenant setting, and flags role/database defaults for it (new `setting` option, code `TENANT_SETTING_DEFAULT`); `findSessionSet` recognises `ALTER ROLE/DATABASE … SET`, `RESET` and quoted names; `withTenant` rejects with `TransactionAbortedError` when Postgres rolled the transaction back; new `relationKeyAudit`.
  - Native engine: tenant creation rotates the session token; a completed password reset invalidates the user's other reset tokens. Better Auth adapter: error-code mapping only reads own keys.
- **Strutvane's own identity engine is now the default (ADR-0023).** This is a breaking release: pre-1.0, breaking changes ride a minor bump (blueprint §8, CONSISTENCY #128). Read "Migrating from v1" in the README.
  
  - **New engine** (from spike 20, with all its tests and both audit rounds): email + password, email verification, password reset, passwordless email links, TOTP two-factor with recovery codes, passkeys (`@simplewebauthn/server`), sessions, personal access tokens, teams and impersonation. Each sign-in option is a feature switch in `config/auth.ts` `features`, using CONSISTENCY #25/#107's names: `password`, `registration`, `emailVerification`, `passwordReset`, `passwordConfirmation`, `twoFactor`, `passkeys`, `emailLink`, `apiTokens`, `teams`, `impersonation`. Every secret is stored as a keyed digest, cookies are `__Host-` on https, and account pre-hijacking is closed (#114, #122). The last-admin guard and the passkey counter are atomic (#117).
  - **Storage** goes through a store port: PostgreSQL (`@strutvane/auth/postgres`, on the framework's `Database` in an app), SQLite (`@strutvane/auth/sqlite`) and memory. The identity tables ship as ordinary migrations (`migrations/{postgres,sqlite}`), applied by `migrate`.
  - **Provider:** it binds `SessionCookieToken`, so the session layer and the framework's CSRF check use one cookie name (#105). The engine's routes are served under `{api}/auth` (Laravel Fortify's names), alongside the v1 endpoints. Mail goes through `AuthMailerToken`. Auth domain events go to the framework event bus: `auth.user.registered`, `auth.login.failed`, `auth.role.assigned`, `tenant.created` and more.
  - **Contract:** `IdentityEngine` error codes are lowercase `snake_case` (#68), plus the new codes `two_factor_required` and `email_not_verified`. Field issues are `{ path, field, code, message }` (#69). Signed links answer 403 `invalid_signature` / `signature_expired` (#67). The contract kit takes each engine's tenant-owner role, which is `admin` for the native engine.
  - **Better Auth is deprecated:** `@strutvane/auth/better-auth` stays, logs one `DeprecationWarning` and is removed no earlier than 0.3. Apps reach it only with `identity: 'better-auth'`. Its v1 package migration moved to `migrations-better-auth/`.
  - **One kernel:** `@strutvane/framework` is a peer (`^0.1.0-next.1 || ^0.2.0-next.0`). Requires Node.js 24.3 or newer.
- 81dcbb0: Depend on the merged `@strutvane/framework` as a **peer** (`^0.1.0-next.1`) instead of `@strutvane/core` and `@strutvane/contracts`. Imports now use `@strutvane/framework/core` and `@strutvane/framework/contracts`, so an app has exactly one kernel: before, installing this package next to the framework added a second copy of core, and its container tokens and error classes did not match the framework's (the logger binding was not found and errors rendered as 500). Requires Node.js 24.3 or newer.
- 6b19ec8: The identity tables ship as a package migration (`migrations/postgres/`, declared through `strutvane.migrations`), so `sv migrate` creates them; `sv auth:migration` is no longer a required step.
- 188fa73: Persistent identity for apps: with `session.driver: 'database'` on PostgreSQL the provider runs the Better Auth engine on the app's database (accounts, sessions, tenants and memberships survive restarts), with the tables written by the new `sv auth:migration` command. The seed admin is created once and never overwritten. Tenant owners manage members over `/auth/tenants/:id/members`. New `@strutvane/auth/admin` (`openIdentityAdmin`: idempotent `ensureUser`, `ensureTenant`, `setMember` for seeders) and commands `auth:user:create`, `tenant:create`, `tenant:member:add`. `IdentityEngine` gains system operations (`findUserAsSystem`, `createUserAsSystem`, `createTenantAsSystem`, `findTenantAsSystem`, `listMembersAsSystem`), `addMemberAsSystem` accepts any configured role and replaces an existing one, and `createBetterAuthEngine` takes `globalRoles`.
- f8364bc: Public sign-up is now off by default. The app provider accepts `POST /auth/sign-up` only when `config/auth.ts` sets `registration: true`; a config that omits the key (or sets any other value) gets the existing `403 FORBIDDEN` problem. Apps that rely on open registration must set `registration: true` explicitly.
- 678a856: Enforce the role map of `config/auth.ts` and add `defineAuthConfig`.
  
  - New `compileRoleMap({ roles, wildcardExclude, newModelDefaults })`. Role permissions (`'<resource>.<action>'` with `*` wildcards, and `{ action, own: true }` for records whose `ownerId` is the actor) become allow grants combined with the policies: `(policy allows OR role grants) AND NOT policy denies`. `own` grants compile to SQL and never match on a model without a text/uuid `ownerId`. Resource wildcards skip `wildcardExclude` resources and, inside a tenant, reach only models with a `tenantId` column. `scope` (`'any' | 'global' | 'tenant'`) works per role or per permission. `newModelDefaults: 'admin-only'` limits unnamed models to the full `'*'` grant. Malformed role maps throw `PolicyDefinitionError` at boot. Without roles, behaviour is unchanged.
  - `createPermissionProvider(policies, { roles, schemas })`: resources without a policy are decided by the role map alone; the provider exposes `roles` and implements `filterableFields(actor, resourceType)` (the readable fields; an unknown resource gets an empty set).
  - Policies accept extra grants: `decide`/`can`/`explain(actor, action, record?, grants?)` and `filterFor(actor, action, grants?)` (new `ExtraGrant` type).
  - The app provider compiles `roles`, `wildcardExclude` and `newModelDefaults` from `config/auth.ts`; a malformed role map fails the boot.
  - New `defineAuthConfig` and `AuthConfig`: a typed `config/auth.ts` (unknown keys are compile errors), deep-frozen like core's `defineConfig`. `AppAuthConfig` is now an alias of `AuthConfig`.

### Patch Changes

- 8614341: The persistent identity (`session.driver: 'database'`) now gives up on a database connection after 10 seconds. Before, a database that accepted TCP connections but never answered (black-holed or wedged) hung the app's boot and every authenticated request indefinitely; now the boot fails and requests fail closed.
- d5ce543: The app provider now enforces policy field rules on the resource API: fields an actor may not read are removed from every record (`resource.serialize`), and creates or updates that send a field the actor may not write are refused with 403 (`resource.beforeWrite`). Previously only filters and sorts honoured read rules.
- 0a17436: Client IP resolution behind a trusted proxy now accepts `X-Forwarded-For` hops that carry a source port (`203.0.113.7:51234`, `[2001:db8::7]:443`), as some proxies send them. Such hops used to be treated as malformed, so every client behind the proxy counted against the proxy's single per-IP rate-limit bucket and one client could block sign-in for everyone.
- 2eaf8eb: The Better Auth adapter now pins Better Auth's origin check for cookie-authenticated writes on. Better Auth switches that check off by itself when it detects a test environment (`NODE_ENV=test`), so a deployment running with that value lost it silently.
- 08fc646: The Better Auth adapter now invalidates every other outstanding password-reset token of a user when a reset completes, matching the native engine. Previously an older reset link stayed usable after the password had been reset. The identity contract suite (`@strutvane/auth/testing`) checks this for every engine.
- 882c509: The Better Auth engine revokes the session the browser presented when a sign-in issues a new one (defence in depth against session fixation), as the native engine already did; the identity contract now checks it for every engine.
- fecc148: The Better Auth adapter now rejects sign-ups with an empty name or a name longer than 200 characters (`VALIDATION_FAILED`), like the native engine and `createUserAsSystem`. Better Auth itself accepted any name.
- 113acb4: A refused tenant switch on the Better Auth engine no longer drops the caller's current tenant (membership is checked before Better Auth is asked). The manifest no longer offers fields an actor may not read and marks fields they may not write as read-only (`manifest.build`).
- ff10dfe: The app provider now answers `POST|GET /auth/tenants` and `POST /auth/switch-tenant` only when tenancy is on (`config/tenancy.ts` `enabled: true`), as documented; otherwise they are 404. Before, any signed-in user of an app without tenancy could create a tenant and act as its `owner`.

## 0.1.0-next.0

### Minor Changes

- First implementation of `@strutvane/auth` (Phase 1/2 core):
  
  - Policy engine: `definePolicy` with a typed predicate builder, allow/deny with deny-wins and deny-by-default, field rules (`readableFields`, `maskRecord`, `unwritableFields`), `explain()` and `Decision.reason` strings; actor binding with the null-never-matches rule; one shared validation gate; in-memory evaluation (`can`) and bound contracts `QueryFilter`s for lists (`filterFor`), proven equivalent on Postgres with property-based tests.
  - `createPermissionProvider(policies)`: the contracts `PermissionProvider`, deny by default.
  - `@strutvane/auth/provider` for Strutvane apps: policies from `app/policies` bound as `PermissionProviderToken`, actor/tenant resolution on `http.onRequest`, sign-up/sign-in/sign-out/me and tenant (create/list/switch) endpoints on the native engine, the `seedAdmin` account, and `defaultRoles`; `createNativeEngine({ globalRoles })` for roles outside tenants.
  - `@strutvane/auth/sql`: parameterised, two-valued, NULL-safe Postgres compiler (strpos/starts_with/right, ASCII-only case folding, correlated scalar subqueries for to-one relations).
  - Tenancy: resolver chain (subdomain, path, trusted-only header, session); `@strutvane/auth/postgres` with `withTenant`, RESTRICTIVE RLS and role migration SQL (ADR-0007), `tenancyAudit`, the `findSessionSet` lint and a shared Postgres rate-limit store.
  - Identity: the `IdentityEngine` interface with `authenticate(request) → { actor, headers }`; a native in-memory engine; the hardened Better Auth adapter (`@strutvane/auth/better-auth`, ADR-0013) with per-IP and per-account limits, trusted proxies only and per-request membership resolution; the contract suite as `@strutvane/auth/testing`.
  - Audit: `recordAudit` with field-level diffs and redaction, the `AuditSink` interface and an in-memory sink.
  - Middleware: framework-agnostic core with Hono (`@strutvane/auth/hono`) and node:http/connect (`@strutvane/auth/node`) adapters.
